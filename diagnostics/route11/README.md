# 고양시 11번 노선형상 국소 진단

저장된 `scripts/fixtures/goyang-11-sanitized.json`의 GBIS 좌표 972개와 경유 정류장 104개만 사용했습니다. 생성 과정에서 GBIS API를 호출하지 않습니다. `geometry.json`의 좌표 번호는 **0부터 시작하는 정규화 배열 인덱스**입니다. 서버 파서가 `lineSeq`로 정렬한 뒤 인접 중복점을 제거하므로 이 스냅샷만으로 원본 `lineSeq` 값을 복원할 수 없습니다.

재생성: 프로젝트 루트에서 `node scripts/diagnose-route-shape-detail.cjs`를 실행합니다. 다른 폴더에 쓰려면 첫 번째 인자로 출력 폴더를 지정합니다. 각 SVG는 왼쪽 원본, 오른쪽 기존 보정 후이며 파란색이 출발 방향, 주황색이 복귀 방향입니다. 화살표는 인덱스 증가 방향입니다. 아래 표에는 각 점의 좌표, 다음 점까지의 거리, 진행 방위, 꺾임 각도, 보정 이동 거리가 있습니다. 녹색 원은 좌표를 옮기지 않은 GBIS 정류장입니다. SVG는 도로 지도가 아닌 좌표 진단도이므로 통행 규제나 실제 운행을 증명하지 않습니다.

로컬 카카오 지도 화면은 PowerShell에서 `$env:BUS_TRACKER_QA_FOCUS_SEQUENCE='36'; node scripts/qa-route-operational-sanitized.mjs`로 다시 캡처할 수 있습니다. `/api` 응답은 저장된 정류장·형상과 익명화된 차량 스냅샷으로 제공되며 운영 GBIS를 호출하지 않습니다. `map-stop36-overview.png`와 `map-stop36-zoom.png`는 이 방법으로 캡처한 화면입니다.

이번 진단에서 앱의 형상 좌표는 **추가로 0점 이동**했습니다. 기존 보정은 58쌍, 116점이며 최대 이동 거리는 6.83m입니다.

- 원본 좌표 `344`, `620`, `626`은 `(37.65363, 126.84048)`로 완전히 같습니다. `340`과 `630`도 같습니다. 그러므로 단일 선의 무작위 연결이 아니라, 두 방향의 접점과 **복귀 방향 안의 되돌림**이 겹쳐 보입니다.
- 원본과 기존 보정 후 모두 이 국소 범위의 엄격한 선분 내부 교차는 0개입니다. 동일 끝점 접촉은 남아 있습니다. 기존 보정으로 움직인 점은 큰 원 범위의 바깥 가장자리 `347`, `617`뿐이며 각각 4.78m, 3.45m입니다. 세 접점과 동쪽 되돌림 자체는 움직이지 않았습니다.
- `340`, `344`, `623`, `626`의 원본 꺾임 각도는 약 103.5°, 123.8°, 147.7°, 128.3°입니다. 이 회전들을 제거하거나 직선 연결하면 원본 순서와 도로 연결 가능성을 훼손합니다. 동쪽 끝의 되돌림이 실제 버스의 유턴인지 확인할 독립적인 운행 궤적·도로 통행 근거는 현재 없습니다.
