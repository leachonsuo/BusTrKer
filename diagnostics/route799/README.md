# GBIS 799 방향 분리 진단

2026-10-11 로컬 Functions Emulator에서 노선 상세·형상·경유 정류장을 각 한 번 조회했다. 실제 routeId는 `229000071`, 표시 번호는 `799`, 유형은 일반형시내버스다. 상세의 기점은 서울여객금촌차고지, 종점은 광화문역6번출구.광화문빌딩이다. [인증키와 차량정보가 없는 정규화 fixture](../../scripts/fixtures/gbis-229000071-sanitized.json)에 정류장 방문 149개, 형상 점 1,466개가 있다. 중복 정류장 ID는 없고, 동일한 형상 좌표는 125종이 여러 인덱스에 나타난다.

현재 작업 트리의 최초 실패 조건은 `splitRouteDirections()`의 `AMBIGUOUS_TURN_MATCH`다. 공식 `turnYn=true` 방문은 72번, ID `100000034`(광화문역6번출구.광화문빌딩) 하나다. 이 정류장으로부터 35m 안이면서 최근접 거리 +10m 안인 별개 형상 방문은 인덱스 약 `718.058`(29.17m)과 `724.016`(23.12m)이다. 형상 진행 거리상 약 159m 떨어진다. 직전 71번 정류장의 최근접 인덱스는 `715.976`, 직후 73번은 `727.188`이다.

첫 번째 회차 후보를 경계 `719`로 잡아도, 두 번째 후보를 경계 `725`로 잡아도 정류장 1–72와 73–149가 각각 기존 35m 기준의 증가하는 형상 후보 조합을 갖는다. 인접 정류장 및 전체 방문 순서로 두 경계 중 하나를 배제할 수 없다. 더 가까운 후보를 택하는 것만으로 실제 회차 시점을 확정할 수 없으므로 `AMBIGUOUS_TURN_MATCH`와 전체 노선 fallback을 유지한다. 현재 코드의 방향 분리 실패는 30번의 정류장별 최근접 후보 오류와 구별된다.

검사 명령:

```powershell
node scripts/diagnose-route-directions.cjs scripts/fixtures/gbis-229000071-sanitized.json
node scripts/diagnose-route-directions.cjs scripts/fixtures/gbis-229000071-sanitized.json 71 72 73
```
